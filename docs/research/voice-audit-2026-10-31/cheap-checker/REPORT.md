# Cheap factual checker experiment alongside integration

The owner asks for continuing DeepSeek/GLM tests while code integration proceeds.
Six OpenCode max calls run offline. No result from this experiment changes live
model routing or installs a new checker gate. The first four calls use ten saved
or synthetic examples in forward/reverse orders. The last two use focused claim
comparison on two error/control pairs. Expected labels remain outside model input.

## What is tested

The checker looks only for unsupported concrete facts, invented owner actions,
changed qualifiers and questions explicitly answered in the source. It does not
reject ordinary taste, immediate affect, hypothetical approval policy or conditional
willingness merely because the wording is critical. A stylistically unwanted
product test can therefore be valid under this narrower factual rubric.

Fixtures A–E are reactions, celebration, policy, affect and conditional preference.
F is the disputed per-call diff-card claim. G claims an actual current repository
download without evidence. H says a bad transfer never returns. I summarizes a
possible agent-created canvas as an agent-built canvas. J asks whether the app
supports git when the source explicitly says so. D and J are synthetic controls.
The rest reuse saved text or exact spans. Parent labels are hypotheses, not gold
owner labels. F and I involve interpretive ambiguity and are not literal source
contradictions. All original source text and expected-label rationale are saved.

## Initial results

| Call | Concrete issues flagged |
| --- | --- |
| DeepSeek forward | G current download, J already-answered question |
| DeepSeek reverse | J already-answered question, G current download |
| GLM forward | G current reading/download, J already-answered question |
| GLM reverse | J already-answered question only |

Both models leave all five non-error controls unflagged, which is useful evidence
that this small rubric need not suppress ordinary social writing. Both accept
the parent-disputed per-call and canvas wording. Neither initially flags the
unqualified transfer assertion. GLM's current-action judgment changes with order.
No broad sensitivity, false-positive or production reliability rate is inferred.

## Focused comparison

Two additional calls ask each model to distinguish preferences from factual
assertions, then compare quantifiers, conditions and feature relationships.
Both models classify the transfer assertion as unresolved because the source
does not establish it. Both accept a personal money-approval rule as nonfactual.
Both accept the corrected card/availability statement.

Both still classify the per-call diff-card sentence as preference and claim its
embedded detail matches the source. This does not settle the source's attachment
ambiguity. It shows that agreement between these two models is not independent
proof that every embedded capability is entailed. They share an interpretation
that the parent and earlier reviewer regard as stronger than the source states.

## Findings for implementation

Current-action claims deserve explicit attention, separate from prior biography.
The canonical Reply contract now makes that boundary explicit. A hypothetical
plan to try a tool is different from saying a download is happening now.
The focused rubric improves one concrete distinction without demanding a citation
for every social act. It does not demonstrate a dependable general semantic gate.
Do not replace the configured independent Writer review with these experimental
checkers, silently add a critic dependency, or call two-model agreement truth.

No third tuning attempt or live claim-check gate follows automatically. The
user permits further calls when they answer new questions, not an output quota.
Token usage and money are unknown. Activity reads show no tool actions and no
omitted pages. GLM's Markdown fences remain raw in the evidence. Derived summary
data decodes those objects for content inspection without a content penalty.
No public action, browser session, service or production database mutation occurs
in these model jobs. Implementation and its checks are recorded separately.
