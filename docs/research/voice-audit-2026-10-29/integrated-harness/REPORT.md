# Growth OS offline reply experiment, 29 October 2026

## Outcome and checkpoint

The offline benchmark works. This experiment does not establish a reply-quality
repair. No new writing prompt or model is selected for production. The native
Harness² composer keeps the baseline. That decision describes this one cycle,
not a general endorsement of the baseline.

Hamza wants a human developer who participates in the actual conversation.
Advice, technical detail, humor, celebration, disagreement and silence can all
fit. The account must not grade every product, invent a problem, assign work,
or add a technical lesson merely to justify a reply. Creative wording and
ordinary affect do not require independent verification. Concrete product
claims and invented personal experience are different concerns.

This checkpoint closes the bounded experiment. It does not close XR-14 or
establish live X, owner-voice, ARM operator or follower-growth acceptance.

## What the implementation does

- Captures the real Growth OS Writer packet, generation schema and review request.
- Enters disposable state before importing store-dependent application modules.
- Saves exact requests, outputs, model settings, receipts and review findings.
- Runs the installed Harness² task-level sequential k=1 recursion.
- Supports a selected writer, reviewer and editor through provider/model/options.
- Compares extra writing fragments without editing production prompt files.
- Replays the attached reply instructions as a separate, limited direct lane.
- Reviews an existing output with another reviewer or review fragment, without
  another generation. Original output and verdict files stay intact.
- Keeps text visible after a failed review. No numeric voice score or pass quota
  selects a winner. Offline review remains diagnostic, not publication authority.

The operating guide is `docs/GROWTH_REPLY_BENCHMARK.md`. Model availability comes
from T3. The adapter emits requests and imports completed execution receipts.
It does not launch a model CLI or select an unavailable replacement.

## Scope and controls

The main case is VA-16, the AndroidHarness source. VA-14, the CodeAlta release,
is a celebration control. Source posts come from the committed audit dataset.
Fixture behavior comes from stored publication context. Missing affect fields
are neutral. These reconstructed fixtures are not historical generation traces.

Packets stay fixed across matched cases. The Writer uses the current full
contract. The direct lane uses the attached brief's reply section and frozen
packet. It omits browser, room, full operator context and history. Its content
review is a diagnostic sidecar. The live `act` path does not invoke that review.
Therefore a diagnostic failure is not proof that the live direct path blocks it.

Earlier small-prompt experiments used less context. This run tests transfer into
Growth OS. It does not establish that the model is incapable of the desired style.

## Review calibration

The new optional fragment is `eval/prompts/review-calibration-v1.txt`. It asks for
the ordinary reading of the conversation. Social acts, immediate affect, humor
and preference need no external citation. It does not demand a technical point,
caveat, question, metric or short style. It retains factual and owner-history
checks for claims that the text actually makes.

Two Terra-high review-only calls reuse frozen outputs. They do not generate
replies, change the original reviews, or edit production enforcement.

- Celebration: the calibrated review stops listing “congrats on 1.6” as a factual
  claim. It still flags the canvas wording and absent product attribution.
- Android baseline: the calibrated review still flags both unsupported causal
  comparisons. It does not merely approve the text to raise a pass rate.

Both complete replies remain blocked. These observations support a narrower
classification improvement on one social span. They do not establish a calibrated
reviewer across topics or resolve the source-attribution contract.

## Findings and causal limits

1. **Generation overreach is real in these samples.** Source features become a
   decisive usability test or unshown failure. That is separate from tone.
2. **Prompt transfer fails in the tested Writer case.** V4's small-prompt behavior
   does not persist inside this full packet. More instructions alone are not a
   demonstrated repair. Both native candidates also fail to establish improvement.
3. **Behavior selection is a leading hypothesis, not a proven root cause.** VA-16
   explicitly requests judgment, opinionated-peer mode and workflow consequence.
   The persona also contains a systems/recovery lens. Those inputs may reward a
   decisive boundary. Source, persona, contract, model and selected behavior were
   not independently varied, so the experiment cannot isolate their effects.
4. **Review extraction can overreach too.** A congratulation need not be a factual
   assertion. The calibration reduces that error without accepting the whole
   reply. Do not describe all factual objections as excessive guardrails.
5. **Attribution needs a scoped decision before production integration.** The
   content standard allows a Reply to rely on visible source context. The review
   instruction and binding code require literal attribution for claims classified
   as source claims. The precise interaction remains unsettled. Do not weaken
   Original/Thread verification or invent attribution to bypass that boundary.
6. **The benchmark and publication workflow have different jobs.** Diagnostic
   findings must remain visible and debatable. A pass is not a public-send claim.
   A failed review must not erase the output or prevent creative offline trials.
7. **Source completeness remains a separate concern.** This run uses fixed audit
   source text. It does not repair or establish live reader fidelity, clipping,
   current source access, or full conversation retrieval.

The fresh independent diagnosis agrees that actual overreach and questionable
review extraction coexist. It explicitly does not establish one causal repair.
Its complete input and response are archived with this report.

## Fresh start: improve one thing at a time

Stop adding style fragments for now. Preserve this run as evidence, not doctrine.
The next cheapest causal experiment changes only VA-16's selected behavior while
holding source, persona, writing contract, model and settings fixed. Compare the
existing judgment packet with one context-appropriate social-participation packet.
Read the actual replies before the review verdicts. Keep factual overreach and
social mismatch as separate observations. Repeat only if the first comparison
leaves a material uncertainty. This next experiment is proposed, not executed.

If behavior drives the unwanted grading, target the selector. If it persists,
test the next specific context component. Do not change behavior, persona, model,
review and prompt together. Use unused sources for validation only after a
candidate change has evidence. Keep Terra optional rather than a required live
writer. The durable benchmark supports whichever available model Hamza chooses.
