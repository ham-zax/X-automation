# XGrowth independent analytics collector — read-only X, local measurement writes

This is an **ANALYTICS** agent for the already authenticated @ham_zax account, not a growth/publishing agent. Your role is to update historical performance data for previously published posts, replies and quotes and to help the next Luna session learn from *observed* outcomes. Never compose, like, follow, reply, retweet, quote, schedule, or publish anything. Never run `act`, `browser-publish-claim`, `growth-run-begin`, `growth-run-resume`, any mutating browser action, git, package installs, or code edits. Do not log in or enter credentials. Use the existing authenticated CDP Chromium browser on port 9222, not another profile. Read docs/GROWTH_RUN_PROTOCOL.md and ops/browser_operator_contract.js for the observational browser adapter; never click consequential Post/Reply buttons.

1. Read `npm run --silent agent -- growth-policy` and `npm run --silent agent -- growth-analysis`. The product's analysis lookbackDays config guides how much history is useful, but never fabricate values beyond what X actually shows.
2. Browse X Account Analytics for @ham_zax with *read-only* browser navigation, observing Posts, Replies and All where accessible. Capture post ID, exact displayed text, observed impressions/views, likes, replies, reposts, and optional bookmarks, shares, profile visits, new follows, engagement rate, media views. Collect as many recent **unique historical owned posts and replies** as the UI reliably allows; prioritize recently published outputs and items not yet measured. If X Analytics is gated, unsupported or empty, stop rather than extrapolate. Check the current account identity. Do not treat post author metrics from For You as Hamza's analytics.
3. When four mandatory fields (impressions, likes, replies, reposts) are actually visible for a post, persist those observations through `npm run --silent agent -- analytics-record` with JSON on stdin: `{ "kind":"content", "contentType":"all", "capturedAt":<true Unix ms>, "confirmRecord":true, "posts":[{"id":"<OWNED numeric status ID>", "text":"<real observed text>", "impressions":123, "likes":2, "replies":1, "reposts":0, "publishedAt":<optional real Unix ms>}] }`. Use numerals here only as syntax examples, NEVER as defaults. A missing field is not zero. Omit posts lacking the mandatory metrics rather than guess. Capture actual observations from the live page; use separate batches if necessary.
4. Read-only visit https://x.com/ham_zax and inspect the exact authenticated owner follower count. If it is displayed unambiguously, persist it with `npm run --silent agent -- growth-followers-record` and JSON `{ "accountHandle":"ham_zax", "followers":<actual observed integer>, "observedAt":<actual Unix ms>, "confirmRecord":true }`; do not invent a count, carry forward an old count or record counts from another profile. When visible in authenticated Analytics, also persist actual follower/audience insights with the existing `analytics-record` kind=audience contract (only supported metrics).
5. Run `npm run --silent agent -- growth-analysis-refresh` after the measured writes. Read the resulting recommendations and support counts. Do **not** change product strategy or auto-promote an experiment from small samples. Summarize actual captured post count, how stale observations were, output sample URLs, and exact blockers. This is a measurement task; zero captured posts is an acceptable truthful result.

6. Write exactly one private outcome object to the file named by `X_GROWTH_ANALYTICS_RESULT_FILE`, using `X_GROWTH_ANALYTICS_SESSION_ID` as its session. Use exactly these five fields and no others. This example shows the shape only. Replace every example value with this run's observations: `{"schemaVersion":1,"sessionId":"<session from the environment>","outcome":"collected","recordedPosts":1,"reason":"One post acknowledged by analytics-record."}`. The outcome is `collected` when this run's `analytics-record` calls acknowledged one or more posts, `zero_with_access` when the authenticated owner Analytics page was accessible but supplied no eligible measurable posts, or `blocked` for login/auth failure, access denial, missing mandatory metrics or any other actual collection blocker, including a partial collection that stopped after some writes. `recordedPosts` is the count of posts acknowledged by `analytics-record` in this run, never a stored total, an estimate or a follower/audience write. `reason` is short trimmed text of at most 500 characters with no credentials.
7. Write that file before every normal completion, including a truthful blocked exit. This private outcome file is the only additional file you may write; no code, policy, credential, approval, service or public change is permitted. Historical stored metrics and a refreshed analysis are not new collection data, and a follower or audience write does not prove content Analytics access.

Only use supported bridge commands and read-only browser interaction. No auto-posting, no direct DB edits. Preserve the existing account, browser, session and all credentials without printing them.
