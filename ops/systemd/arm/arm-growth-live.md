Command sheet (payload → result fields you need):
- `operator-status` `{}` → compact cockpit: delegation, health, lease, readiness. `{"detail":true}` only when a needed field is missing, and at most once per session.
- `queue` `{"draftStatus":"draft","status":"approved","limit":5}` → `{drafts,queueItems,compact,detailHint}`. When readiness indicates saved work, read this once before broad collection. Use `status:"needs_review"` instead when preparing items awaiting review under the current permitted operations. The draft and queue status filters are independent. Keep the result until the queue changes. Read `workflow {"key":"<selected candidateKey>"}` only for the selected item. Do not probe unfiltered queue history or repeat the same drafts without a state change. Queue output grants no approval or send authority.
- `growth-run-begin` `{"adapterType":"claive_unattended","sessionId":"{{SESSION}}","capabilities":{"reasoning":true,"browser_read":true,"browser_mutation":true,"x_authenticated":true,"primary_source_web_research":true},"ceilings":{"maxDurationMinutes":35,"maxPublicMutations":25}}` → `{run:{runId,status,stage,leaseId}, delegation:{allowed,reason}, readiness, next}`. Set each capability truthfully. An already active run is resumed, not replaced. Without the duration ceiling the run stops at 20 minutes.
- `growth-run-next` `{"runId":"…"}` → the same object; read `.next.recommendedOperation`, `.next.permittedOperations`, `.next.stopReason`, `.next.ceilings`. Fields are nested under `.next`.
- `growth-run-status` `{"runId":"<known runId>"}` → `{protocolVersion,run,delegation,readiness,next}`. Read `.run.status`, `.run.sessionId`, `.run.leaseId` and `.next`. Terminal or disallowed runs have `.next:null`. This read does not renew the lease. Never substitute a sessionId for runId.
- `growth-run-finish` `{"runId":"…","status":"completed|partial|blocked|unresolved","stopReason":"…","stopDetail":"…","result":{…}}` → the same object with `.run.status` terminal and `.next` null. stopReason is one of no_worthwhile_eligible_work, resource_ceiling_reached, run_deadline_reserve_reached, delegation_revoked, delegation_revised, capability_unavailable, reconciliation_scope_blocked, manual_intervention_required. Use run_deadline_reserve_reached when the session time limit ends the run, and resource_ceiling_reached only when `growth-run-next` reports a ceiling.
- `x-read` `{"kind":"mentions"}`, `{"kind":"own-replies"}`, `{"kind":"post|thread|replied","id":"<tweetId>"}`, `{"kind":"search","query":"<X search query>","mode":"top|latest"}` → `{ok, posts:[{id,author,text,inReplyTo,at,likes,replies,reposts,views,url}]}`; `replied` returns `{replied, target, ourReplies}`.
- `x-read` `{"kind":"replies","id":"<tweetId>","mode":"top|latest"}` → `{ok, target, mode, observedAt, count, posts}`. `mode` defaults to `top`. At most 40 search candidates and 20 posts by default, 40 at most. A bounded sample: not complete thread coverage and not proof of absence.
- `engage-refresh` `{"refreshResponses":true}` → `{refresh:{refreshed,rejected,expired,errors}, accountHealth, activeConversations, newOpportunities, nextStep}`. Use it in the response phase of a pass to collect replies to our posts through the HTTP mention reader. Optional `{"refreshTargetTimelines":true}` invokes the existing HTTP creator refresh for saved relationship and watchlist targets. Omit both flags for a local refresh with no network. Treat `refresh.errors` as collection blockers, never as zero responses.
- `x-for-you-ingest` `{"kind":"x_for_you","observedAt":<date +%s%3N>,"accountHandle":"ham_zax","adapterType":"claive_unattended","runId":"…","sessionId":"{{SESSION}}","browserTarget":"linux","browserBackend":"chrome","sensorVersion":"x_for_you_v1","collectionStatus":"complete","posts":[{"tweetId":"<numeric ID>","url":"https://x.com/<author>/status/<ID>","username":"<author>","text":"<exact text>","rank":1,"metrics":{"views":<number>}}]}` → `{ingest, engagement:{refreshed,rejected,rejections}}`. `browserTarget` is `linux` on this host; the value is recorded as provenance. Include only observed metrics, mark ads `"promoted":true`, never invent text, IDs or metrics.
- `growth-refresh` `{"kind":"x_momentum"}` → `{refreshed:[{kind,fetchedAt,attemptedAt,candidateCount,preservedLastGood,error}],nextStep}`. Use only on Trending passes. This refresh collects and saves candidates. A non-null error is a collection failure, even when old candidates remain.
- `growth-next` `{"refresh":false}` → `{snapshots,items,topicBalance,readOnlyPlanning,nextStep}`. Read the saved candidates after the Trending refresh. Do not use `refresh:true` here, which also refreshes another source.
- `growth-focus` `{}` → `{groups:[{tag,label,role,weight,terms}]}`: the saved topic groups with their first terms. Read it once per session.
- `scout` `{"limit":12}` → `{pace, cardGuidance, cards}`. It ranks saved candidates only; it does not collect X. `cardGuidance` and the T2 card repeat between passes.
- `writer-generate` `{"key":"<routed candidateKey>","runId":"…","sessionId":"{{SESSION}}"}` → `{draft,queueItem,analysis,decision,writerInvocationId,writer}`. Use an existing routed draft and saved writing-strategy choice. The selected Writer generates and the existing server review checks it. For Quotes use the saved body, draftId, writerInvocationId and behavior unchanged with `act`; Originals and Threads retain queue approval and browser claim. This command never sends.
- `reply-generate` `{"runId":"…","sessionId":"{{SESSION}}","targetUrl":"https://x.com/<author>/status/<ID>","candidateKey":"…","card":{"sourceText":"<exact observed source>"}}` → `{status,text,draftId,behavior,writerInvocationId,writer,replyReview}`. Optional `behavior` is advisory ACT behavior. Omit it to let the Writer choose. Omit `conversationContext` for automatic collection of up to 20 replies. If supplied, context is `{sourceUrl,partial,posts:[{id,url,text}]}`. Evidence entries are `{id,resolvedUrl,summary,partial,status}` with status `source_claim` or `primary_supported`; use `sourceKind:"image_observation"` for observed photo details. Combined context and evidence stay within 16000 characters. For `generated`, pass exact text, draftId, saved behavior and writerInvocationId to `act`. A returned input error includes `{code:"reply_input_invalid",retryable:true,phase:"preparation",nextStep}`. Correct it and retry preparation. An operational error is not a content rejection. This command never sends or grants authority.
- `act-target-status` `{"targetTweetId":"…","candidateKey":"…"}` → `{eligibleForAttempt, reason, existing}`. Call it before writing for a target.
- `social-status` `{"action":"follow","username":"<observed author>"}` or `{"action":"like|repost","username":"<observed author>","targetUrl":"https://x.com/<observed author>/status/<ID>"}` → `{action,targetUrl,alreadyFollowed,existing,existingPublicInteraction,canClaim,advisory:true}`. - `act` `{"action":"reply|quote","text":"…","targetTweetId":"…","targetUrl":"https://x.com/<author>/status/<ID>","runId":"…","sessionId":"{{SESSION}}","candidateKey":"…","card":{"author":"…","sourceText":"<exact source text>","cardId":"…"}}`; profile-written Replies and Quotes also pass `draftId`, saved `behavior` and `writerInvocationId` from their Writer command. These are measurements, never required authority or a reason to act; omit unobserved values and never invent a count. `{"status":"needs_rewrite"}` means rewrite the text, not retry it. An uncertain result is never retried.
- `record-disposition` `{"key":"<candidateKey>","state":"skip|defer","reason":"…"}` for a saved candidate; the field is `key` and the reason is required. Use `defer` with `expiresAt` for recoverable operational blockers. Use `clear` to remove a stale disposition after checking the exact candidate and its publication fence.
- `relationship-context` `{"username":"<author>"}`; `not_tracked` is normal for a new person.
- `publication-attempts` `{"runId":"…"}` → this run's attempts in full. `{}` returns non-terminal attempts, the ten newest terminal ones and `counts` (about 35 KB): use it only to recover work from an earlier run. Check sends with this command, never with SQL on the database.
